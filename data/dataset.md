# Датасет

## Как получить датасет?

```bash
pip3 install pandas pyarrow spacy huggingface_hub
python3 -m spacy download en_core_web_sm
cd data 
python3 build_data.py
```

Скрипт сам скачивает SQuAD v1.1 с Hugging Face. После выполнения скрипта, данные буду лежать в той же папке, где и `build_data.py`

## Как устроен датасет?

Основа — SQuAD v1.1. Части train и validation объединены: все абзацы обеих частей образуют одну общую базу для поиска. Колонка `role` у вопроса показывает только то, из какой части SQuAD он взят. Вопросы train используются в блоках 1–2 (Елена, Виктор), вопросы valid — в блоке 3 (Кирилл).

Пять таблиц и связи между ними:

```
contexts (pid) ──< chunks (chunk_id, pid)
      │                    │
      └──< questions (qid, pid, orig_qid)
                 │         │
                 │         └──< answer_chunks (orig_qid, chunk_id) >── chunks
                 └──< answers (orig_qid)
```

### contexts.csv — абзацы

| колонка | описание |
|---|---|
| `pid` | id абзаца, ключ |
| `title` | название статьи Википедии |
| `context` | текст абзаца |
| `n_chunks` | сколько кусков получилось из абзаца |

### chunks.csv — куски абзацев

Кусок — это окно из 2 предложений, которое сдвигается на 1 предложение. Предложения выделяет spaCy (`en_core_web_sm`). Соседние куски пересекаются на одно предложение. Абзац из одного или двух предложений целиком становится одним куском.

| колонка | описание |
|---|---|
| `chunk_id` | id куска, ключ |
| `pid` | абзац, из которого взят кусок |
| `chunk_no` | номер куска внутри абзаца |
| `start`, `end` | границы куска в символах: `text == context[start:end]` |
| `text` | текст куска |

### questions.csv — вопросы и перефразы

| колонка | описание |
|---|---|
| `qid` | id вопроса, ключ |
| `squad_id` | id в SQuAD; у перефразов пусто |
| `orig_qid` | `qid` исходного вопроса; у исходного вопроса совпадает с собственным `qid` |
| `role` | `train` или `valid` |
| `is_paraphrase` | `True` у перефраза |
| `pid` | абзац, к которому относится вопрос |
| `question` | текст вопроса |

Перефразы сделаны для 2000 вопросов из train и 500 из valid, не больше одного вопроса на абзац, seed 42. Перефразировала большая LLM. Имена собственные, даты, числа и названия сохранены, остальное сказано другими словами, ответ в перефраз не попадает. Доля значимых слов вопроса, которые встречаются в абзаце, снизилась в среднем с ≈0.67 до ≈0.33.

### answers.csv — эталонные ответы

| колонка | описание |
|---|---|
| `orig_qid` | исходный вопрос |
| `text` | текст ответа |
| `start` | позиция ответа в абзаце: `context[start:start+len(text)] == text` |

На один вопрос может приходиться несколько ответов: в valid у вопроса бывает несколько разметок. Повторы пар (`text`, `start`) удалены. У перефразов своих строк нет, их ответы берутся по `orig_qid`.

### answer_chunks.csv — куски, в которых есть ответ

| колонка | описание |
|---|---|
| `orig_qid` | исходный вопрос |
| `chunk_id` | кусок |
| `is_annotated` | `True` — в куске целиком лежит размеченное вхождение ответа (по `start`); `False` — только неразмеченное вхождение того же текста ответа целым словом в другом месте абзаца |

Отсюда два варианта эталона:
- **строгий** — куски с `is_annotated = True`;
- **мягкий** — все куски из таблицы.

Куски пересекаются, поэтому эталонных кусков у вопроса может быть несколько.

### Исключения

Вопросы, ответ на которые не попал целиком ни в один кусок (3 вопроса), удалены из `questions` вместе с их перефразами, а их строки удалены из `answers`. `qid` после этого не перенумерованы, поэтому в нумерации есть пропуски.

### Размеры

| таблица | строк |
|---|---|
| contexts | 20 958 |
| chunks | 82 222 |
| questions | ≈98,2 тыс. исходных + ≈2 500 перефразов |
| answers | ≈105,8 тыс. |
| answer_chunks | 160 386 (из них `is_annotated = True`: 146 780) |

Точные числа `build_data.py` печатает в конце работы.

### Чтение в pandas

В `answers.csv` есть ответы `None` и `null`. По умолчанию pandas превращает их в NaN, поэтому этот файл читается с `keep_default_na=False`.

```python
import pandas as pd

questions = pd.read_csv("data/questions.csv")
chunks = pd.read_csv("data/chunks.csv")
answers = pd.read_csv("data/answers.csv", keep_default_na=False)
answer_chunks = pd.read_csv("data/answer_chunks.csv")
```

## Почему так устроен?

- **SQuAD v1.1.** У каждого вопроса ответ гарантированно есть в его абзаце и размечен позицией в тексте. Поэтому можно автоматически проверить, попал ли ответ в найденный кусок. 
- **Одна база из train и valid.** Векторный поиск ничего не обучает, поэтому делить абзацы на части незачем. Чем больше база, тем ближе задача к реальной и тем заметнее разница между индексами. Разделение по `role` осталось только у вопросов: блоки 1–2 и блок 3 работают на разных вопросах, и выбор модели и индекса не подгоняется под вопросы, на которых проверяются ответы LLM. Кроме того, в valid у вопроса обычно несколько вариантов ответа от разных разметчиков, и по ним ответы LLM оцениваются точнее.
- **Куски по 2 предложения.** У целых абзацев кандидатов меньше, а текста в каждом больше, поэтому поиск по ним проще и меньше похож на реальный RAG. Одного предложения мало: слова вопроса и сам ответ часто стоят в соседних предложениях. Режем по предложениям, а не по числу токенов, чтобы граница куска не проходила посреди фразы.
- **Сдвиг на 1 предложение (куски пересекаются).** Любые два соседних предложения целиком лежат в каком-то куске. Поэтому ответ, который начинается в одном предложении и заканчивается в следующем, не теряется.
- **Два эталона.** Строгий эталон — кусок с тем вхождением ответа, которое отметили разметчики. Но текст ответа часто повторяется в абзаце ещё раз, и кусок с таким повтором тоже позволяет ответить; считать его промахом несправедливо. Мягкий эталон такие куски засчитывает, но может засчитать и случайное совпадение слова в другом смысле. Сравнение двух эталонов показывает, насколько выводы зависят от выбора эталона.
- **Поиск ответа только целыми словами.** Иначе ответ «11» нашёлся бы внутри «1911», и в мягкий эталон попали бы лишние куски.
- **Отдельные таблицы `answers` и `answer_chunks`.** В ячейках нет списков (первая нормальная форма), поэтому таблицы без преобразований загружаются и в pandas, и в любую СУБД и соединяются по ключам. Ответы и эталонные куски привязаны к `orig_qid`: у перефраза те же ответ и эталон, что у исходного вопроса, поэтому они не дублируются.
- **Перефразы.** Разметчики SQuAD писали вопросы, глядя на абзац, поэтому в вопросах много слов из абзаца (в среднем ≈0.67 значимых слов). Это даёт фору BM25, который ищет по совпадению слов, и не проверяет, находит ли векторный поиск ответ по смыслу. Перефразы снижают эту долю до ≈0.33. Имена, даты и числа оставлены, потому что реальный пользователь написал бы их так же. Берётся не больше одного вопроса на абзац, чтобы перефразы покрывали много разных абзацев, а не скапливались в нескольких.
- **Исключённые вопросы.** Если размеченный ответ не попал целиком ни в один кусок, такой вопрос в строгом эталоне всегда считался бы промахом, и строгий и мягкий эталоны оценивались бы на разных наборах вопросов. Это артефакт нарезки, а не свойство методов поиска. `qid` не перенумерованы, чтобы ссылки `orig_qid` у перефразов остались верными.
