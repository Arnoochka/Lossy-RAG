# Воспроизводимость: что именно можно повторить

## 1. Проверка результатов без моделей

Нужен Python 3.12. Из корня репозитория:

```bash
python -m venv .venv
```

Windows PowerShell (активация не требуется):

```powershell
.\.venv\Scripts\python.exe -m pip install -r experiments/block1/requirements-block1.txt
.\.venv\Scripts\python.exe experiments/block1/scripts/verify_manifest.py
.\.venv\Scripts\python.exe experiments/block1/scripts/audit_release.py --tables-only
```

Linux/macOS: вместо `.\.venv\Scripts\python.exe` использовать `.venv/bin/python`.
Все ошибки дают ненулевой exit code. Отчёты находятся в `experiments/block1/local_checks/`.

## 2. Полный аудит датасета и имеющихся Small-векторов

Распаковать архив данных в корень этого репозитория: должны появиться
`data/chunks.csv`, остальные четыре CSV и `data/embeddings_bge-small-en-v1.5/`.
Запустить `python experiments/block1/scripts/audit_release.py` без `--tables-only`.
Это заново проверяет связи и текстовые позиции, строит весь строгий/мягкий эталон,
пересчитывает метрики перефраз по выдаче и выполняет точный поиск BGE Small.

При необходимости вернуть выборку запросов в исходное состояние:
`python experiments/block1/scripts/prepare_block2.py --sample main`.
Основной `query_hash` из научных CSV относится к 511 вопросам (500 оригиналов + 11 перефраз).
Каталог для блока 2 по умолчанию содержит **только 500 оригиналов**, поэтому его набор запросов другой.
В отдельном эксперименте перефраз — 1 000 запросов (500 + 500) с собственным хэшем.

## 3. Сборка корпуса

В готовой поставке корпус уже есть. Для независимой сборки:

```bash
python -m pip install -r experiments/block1/requirements-data.txt
python data/build_data.py
```

Сборщик сохраняет CSV в каталог `data/` независимо от текущей рабочей папки.
Источник SQuAD закреплён на revision `7b6d24c440a36b6815f21b70d25016731768db1f`;
spaCy 3.8.18 и модель `en_core_web_sm` 3.8.0 дали совпадающий корпус.
После пересборки обязательно выполнить полный аудит: одного совпадения количества строк недостаточно.

Контроль: 82 222 фрагмента,
`doc_hash=15704f7b9c5a2a21f5484613e837786e00afc7d596014eb82832dfb0732fb4af`.
SHA256 байтов CSV исторического Windows-файла отличается от Linux-файла из-за окончания строк;
для совместимости векторов используются отпечаток содержимого и порядок `chunk_id`.

## 4. Проверка функций и интеграции

```bash
python -m pip install -r experiments/block1/requirements-tests.txt
python -m unittest discover -s experiments/block1/tests -v
```

Сюда входят граничные равенства top-k, изменения векторов при возобновлении,
инвалидация кэша PCA, некорректные значения матриц, идентичность перефраз и
небольшие реальные проверки BaseSearch, IVF, HNSW, BM25, SQ, BQ и PQ.
Для сборки hnswlib при отсутствии подходящего wheel требуется C++ компилятор.
Это не требуется для проверок разделов 1–2.

## 5. Новый нейросетевой прогон

Не требуется для использования переданных результатов и Small-векторов.
Запускать в отдельном модельном окружении; его совместимость с конкретным GPU/Windows
не подтверждалась этим аудитом. В ноутбуках есть инструкции по зависимостям.

1. `notebooks/01_BGE_и_PCA.ipynb` — BGE Small/Base/Large и PCA Small.
2. `notebooks/02_Nomic_Matryoshka_PCA.ipynb` — Nomic full, Matryoshka и PCA.
3. `notebooks/03_Перефразирование_500.ipynb` — запросы 500 пар, с готовыми документными кэшами.

Корень определяется по каталогу репозитория либо через `LOSSY_RAG_ROOT` во всех трёх ноутбуках.
Пример перед запуском Jupyter: `$env:LOSSY_RAG_ROOT = 'D:\Lossy-RAG'`.
Код использует только `ROOT/data`; автоматическая подстановка случайной папки данных отключена.
Выборки берутся из опубликованных CSV; другой корпус вызывает ошибку.
Новые вычисления записываются в `lossy_rag_final_results_safe/` и `lossy_rag_paraphrase_results/`.

Исторические ревизии нейросетей и точный freeze машины исходного запуска не сохранились.
Поэтому новый прогон не следует называть побитовым повторением первоначального кодирования.
Перед новым прогоном зафиксировать `pip freeze`, model revision, устройство и параметры кодирования.
Nomic использует LayerNorm перед последующими преобразованиями и L2-нормировку для косинусного поиска.

## 6. Экспорт дополнительных документов

```bash
python experiments/block1/scripts/export_handoff.py --root D:/Lossy-RAG --out D:/Lossy-RAG-handoff
```

Выходная папка должна быть новой. По умолчанию экспортируется проверенный Small и корпус;
`--include-vectors all` дополнительно требует исходные Base/Large/Nomic кэши.
Экспорт проверяет весь набор до записи, значения/нормы векторов и соответствие корпуса,
затем формирует хэши всех файлов. Отсутствующие матрицы не создаются из результатов CSV.

## 7. Статистические и предметные ограничения

Все выборки блока 1 — train. Valid используется отдельно в блоке 3.
Сравнения с Small используют сохранённое семейство 31 теста для Холма;
Nomic MRL/PCA — четыре теста; падение при перефразировании — три теста;
сравнение устойчивости между BGE — три перестановочных теста.
Смысловая эквивалентность перефраз требует экспертного аудита.
